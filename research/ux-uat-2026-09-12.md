# Infrastructure assessment UX and performance audit — 2026-09-12

The initial map displays much more information than a new visitor can use. A category-first Explore list should be the default; Map remains a deliberate spatial exploration mode and retains explicit deep links. This is a design recommendation from task analysis and rendered inspection, not a user-study result.

## Method and scope

Local Chromium through the repository's installed Python Playwright runtime, fresh browser context at 375×812, 768×1024, and 1440×900. Tested landing and navigation through Rankings, Microreactors, Nuclear Siting, Nickel Refining and About. Captured screenshots, page errors, resource timing, long tasks, approximate heap and DOM size. Server was Python `ThreadingHTTPServer`, uncompressed and unthrottled; measurements are diagnostic lab observations, not production or field Core Web Vitals. No packages installed.

Artifacts: `/tmp/brownfield-uat-2026-09-12/` contains `baseline.json`, per-width screenshots and the repeatable audit script. Images are outside `docs/`, so they cannot enter the production deployment. Transient `/tmp` artifacts are not a durable archive.

## What the rendered pages show

- Mobile map legend consumes nearly half the map width and roughly 438 px vertically. Its 15 categories obscure the small national map. Collapse the legend on mobile and defer optional overlay catalogs until requested.
- Mobile Rankings displays rank, site, state and acreage, but the score itself is beyond the visible right edge. Replacing one numeric column with many category columns would reproduce the problem. Use a stacked evidence summary per site on small screens; put evidence before supporting measurements.
- Nuclear Siting spends the first mobile screen on a long introduction. Put a short purpose statement, class selection and first sites first. Move method prose to a disclosure; show water, grid and land unknowns next to each site.
- Eleven horizontally scrolling tabs make later categories hard to discover on mobile. Keep a clearly labeled Explore entry and a visible way to select the intended use; preserve direct category links.
- Corpus metrics such as “Datacenter-ready”, “Hyperscale-ready”, “Generation-ready” communicate readiness unsupported by proximity evidence. Replace them with selected-site counts and coverage: grid mapped, water evidence, fiber unverified, land unknown. Name the denominator and distinguish full corpus from current selection.
- National point clouds can help geographic orientation but do not answer why one site deserves investigation. List-first supports comparison and source access; map-first remains useful for an explicit location or selected site.

## Recommended interaction contract

1. Default Explore shows site name, location and separate category findings. Findings and confidence are different fields.
2. A finding says what is known: mapped feature nearby, constraint documented, or unknown. Confidence describes support for that finding: High, Medium or Low. No numeric total, hidden numeric sort or numbered rank.
3. Expand a site for measurements, source, source date, geometry basis and the next missing verification. Show exact distances as measurements rather than precision in suitability.
4. Unknown stays visible. Missing fiber is not poor connectivity; no public grid match is not off-grid; streamgage distance is not supply-water availability.
5. Global filters apply only to shared-corpus views. Curated tabs identify their separate populations.
6. Load programs and required category evidence first. Load documents, AI summaries, NEPA dossiers and optional map overlay catalogs with the surface that needs them. Failed loads must say unavailable, not no match.
7. Keep tab mounts lazy, bound retained row counts and test a multi-tab session as well as first load.

## Performance implementation handoff

A reviewable scheduling/legend patch is at `/tmp/brownfield-perf.patch`; it was generated without editing shared `docs/app.js`. It defers noncore catalogs and details, adds explicit detail/Map loading boundaries, collapses mobile legend and gates the initial ready signal on core settlement. The integrating agent owns application edits and tests the final result.

Avoid allocating all Leaflet markers for list-only visits. Keeping the map instance for existing selection helpers while delaying `addMarkersForRecords` / `hydrateMarkersChunked` is a smaller change than removing all map initialization. Map readiness must await core program ingestion plus a final hydration pass; initial tab routing currently precedes creation of program-loading promises, so a naive `Promise.allSettled` in the route fires early.

## Current primary guidance

Google recommends examining the complete LCP path and comparing lab observations with field data; good LCP is at most 2.5 seconds at the 75th percentile. This audit does not claim field compliance. [web.dev: Optimize LCP](https://web.dev/articles/optimize-lcp)

Large DOMs can make rendering and interactions expensive. Reduce rendered content and avoid adding hidden DOM merely because content is visually hidden. This supports bounded list rendering and multi-tab-session measurement. [web.dev: DOM size and interactivity](https://web.dev/articles/dom-size-and-interactivity)

Interaction latency includes input delay, processing and presentation. Splitting long work and reducing rendering cost helps; fast initial paint alone does not establish responsive filtering or tab changes. [web.dev: Optimize INP](https://web.dev/articles/optimize-inp)

## Implemented changes

Explore is the default route, with alphabetical site rows and separate grid, fiber, water, land and logistics findings. Confidence is attached to a finding, not to overall suitability. Mobile and tablet rows become evidence cards using the same table DOM. Nuclear rows expand for source detail; closed details remain hidden even when responsive row styles use CSS grid. The Data & methods tab explains source coverage, uncertainty, the unimplemented High-confidence verification standard and the editorial 730-day context policy.

The application now defers optional evidence and overlay catalogs to their views, allocates site markers on Map activation, and builds the main Table only when used. Mobile coverage metrics and the map legend are disclosures. Category tests use core readiness; map tests await marker readiness. A retained legacy map test compared pane-relative transforms to map height; it now checks screen-space bounding rectangles after hydration.

Browser suites have been migrated from retired numeric formulas to category contracts. Preserved checks include land-threshold boundaries and unknowns, source citations, CSV consistency, keyboard expansion, empty filtered views, optional-load errors/retries, program-join races and Alaska marker remapping. Forced join tests explicitly activate deferred evidence while program responses are delayed, preserving the race rather than merely increasing timeouts.

## Approach C pilot follow-through

The Explore row and detail drawer now expose scoped regional/network evidence instead of hiding it behind Unknown. Water shows the named HUC12 and linked NHD flowline; fiber says regional footprint; both name unresolved parcel questions. Data & methods counts the pilot without describing it as enterprise serviceability. Portsmouth shows named grid equipment, asset scope and the capacity/rights gap.

PR CI also exposed two late-suite detail-panel waits that used a three-second visual selector despite the application state already being visible. The tests now wait on the `hidden` state contract for up to ten seconds, and CI uses two Chromium workers, matching the repository's resource-pressure guidance.
