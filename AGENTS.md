# AGENTS.md — Universal Development Principles

> Distilled from patterns across multiple projects. Apply universally; skip sections irrelevant to the current project type.

---

## Agent Workflow: Explore → Plan → Code → Verify

Never blindly write code. Always follow this loop:

1. **Explore** — Search the codebase. Find relevant files, understand existing patterns before touching anything.
2. **Plan** — Assess the blast radius (how many files touched, how long it takes). For significant changes, present 2–3 high-level approaches with pros/cons and ask for human approval before writing code.
3. **Code** — Implement following the rules below.
4. **Verify** — Run tests. Fix all failures before declaring the task complete.

**Read before edit:** Always read a file before editing it, even if it was read earlier in the conversation.

**Ask for options first.** On non-trivial tasks, propose approaches before writing code. The human needs to evaluate options — don't assume the first plausible approach is the right one.

---

## Communication Style

- **Concise output.** No filler, no apologies, no moralizing. Skip generic advice.
- **Show your work.** Use short internal monologues to break down complex problems.
- **Fail loud.** Never use catch-all exception handlers that silently swallow errors. Always raise or log explicitly.

---

## Architecture Principles

- **No over-engineering.** Only make changes directly requested or clearly necessary. Keep solutions simple.
- **Single source of truth.** Constants, configs, and shared types derive from one place.
- **Modular design.** Separate concerns: data fetching, processing, storage, and presentation are distinct layers.
- **Idempotent operations.** Re-running any operation should be safe and produce the same result. Use `INSERT OR IGNORE` patterns, cache checks, or deduplication by unique key.
- **Static when possible.** Prefer baked-in data over runtime backends when the data update cycle allows it.
- **Cost-optimized.** Stay on free tiers and use the cheapest resources that meet requirements.
- **CLI-first.** Build CLI entry points before UI. Agents can invoke CLIs directly to self-validate output, closing the feedback loop without human intervention.
- **Minimize page weight and request count.** Audit total payload size and number of requests. Content-focused sites should be lightweight — aim for fewest requests and smallest payload possible.
- **Tree-shake and code-split.** Don't bundle every controller/feature for every page. Use code-splitting and lazy loading so pages only load the code they actually need.
- **Benchmark against best-in-class.** Compare your site/app against well-optimized reference points. If the simplest site in your org is orders of magnitude lighter, your build process needs review.
- **Document subsystems.** Maintain a `docs/` folder with notes on non-obvious subsystems, design decisions, and correct CLI invocations. One line of documentation prevents repeated mistakes.

---

## Error Resilience

- **Never let a single item failure crash the pipeline.** Wrap individual record processing in try/except. Log and continue.
- **Log aggressively.** Every request, parse, API call, cache hit/miss, and filter decision should be logged.
- **Cache everything.** Re-runs should be fast and cheap. Multi-layer caching where appropriate.
- **Validate everything.** Invalid responses from external services → log and skip, never crash.
- **Track errors visibly.** Use an `issues.md` file or errors array — failures must be visible, not silent.

---

## Security & Credential Handling

- **Never commit secrets.** API keys, tokens, and passwords must never appear in committed code.
- Read credentials from environment variables only (e.g., `os.environ["API_KEY"]`). Halt with a clear error if missing.
- Never log or print credential values.
- Always `.gitignore`: `.env`, `.env.local`, `credentials.json`, `secrets/`, `node_modules/`, `__pycache__/`, `dist/`, `*.pyc`.
- Before committing: `git diff --cached | grep -iE "apikey|password|token|secret"`.
- **Respect user privacy choices.** Don't circumvent ad blockers or privacy tools by proxying tracking SDKs through your own domain. This erodes user trust.
- **Check the vibe-coding security index before suggesting `npm install` or `pip install`.** Pranava maintains a living index of supply-chain attacks, malicious npm/PyPI packages, AI IDE prompt-injection vulns, and MCP server compromises at https://pranava0x0.github.io/vibe-coding-security/llms-ctx.txt (compact, ~12KB). WebFetch it before recommending an install command; if the package or pattern matches an open advisory, surface the warning — severity, TL;DR, and the index's diagnostic command (bash/npm/pip "am I affected?" check) — BEFORE the install suggestion so the user can decide. The index is small enough to scan in-context; don't skip it as "probably fine." Covers slopsquatting (AI-hallucinated package names), Shai-Hulud-class worms, and known-bad MCP servers — all of which are exactly the failure modes an LLM is most likely to suggest.

## Testing & Validation

- **Write tests alongside code, not as an afterthought.** Every new module or bug fix includes corresponding tests.
- Write a regression test for every bug fix.
- Validate output data against expected schemas before writing to disk.
- **Cover edge cases, not just happy paths:**
  - Empty input: `[]`, `{}`, `""`
  - Null/undefined for every optional field
  - Boundary values (first/last page, exact date boundaries, zero counts)
  - Combined states (e.g., multiple filters active simultaneously)
- Run the full test suite before committing to catch regressions.
- **Never ship test files to production.** Ensure build pipelines exclude test files, dev fixtures, and debug artifacts from production bundles. Use build exclusions and CI checks to enforce this.

## Git Discipline

- **Before starting ANY work, find the latest thing to pull from — don't assume local `main` is current.** Run `git fetch origin --prune` first, then check for the newest state across three places: (1) the latest commit on `origin/main` (`git log --oneline -5 origin/main`), (2) any open PRs (`gh pr list --state open`), and (3) any newer feature branches (`git branch -a --sort=-committerdate | head`). Base new work on whichever is authoritative — usually `origin/main`, but sometimes an in-flight PR branch. This repo's `origin/main` history has been **force-rewritten** at least once (2026-07-09: `5a7dbac` → `595dda4`, identical trees, every hash changed all the way back), which leaves local `main` "diverged" even though content matches. When that happens, confirm the tip trees are identical (`git diff --stat <local> origin/main` → empty) and `git reset --hard origin/main`. Feature branches created before a rewrite sit on the *old* base, so their "N commits behind" count is rewrite noise — the real unmerged work is only their commits whose *content* isn't in `origin/main` (verify with `git diff origin/main..<branch>`, and rebase/cherry-pick those specific commits onto current `origin/main` rather than a raw `git merge`).
- **Commit often** at natural checkpoints — small, focused commits over large monolithic ones.
  - After each new module/feature is built
  - After fixing a bug or resolving a failing test
  - After updating documentation
- Write descriptive commit messages explaining *what* and *why*.
- Never commit large binary files, downloaded data, or API keys.

## Data Handling

- **Append-only data.** Append new records rather than overwriting. Deduplicate via unique keys.
- **Source attribution.** Every data record must include its origin (source URL, connector name, etc.). Users must be able to trace data back to its source.
- **Defensive optional field handling.** Null-check every optional field before rendering or processing.
- Null values show explicit placeholders ("N/A", "TBD", "Value TBD") — never blank UI elements or missing fields.

## Issue Tracking (`issues.md`)

Maintain a living `issues.md` in the project root as an audit trail.

- Log bugs with: date, module/area, description, root cause (**code bug** vs. **test bug**), and status (Open / Fixed).
- Update entries when resolved: what the fix was + the commit that resolved it.
- After every bug fix, check whether a new regression test is needed.

---

## Backlog (`backlog.md`)

Maintain a `backlog.md` for ideas, features, and enhancements.

- When ideas come up during development, add them immediately — don't lose them.
- Each item: brief description + priority (low / medium / high).
- Review and reprioritize periodically.

## Python Standards

*(Apply when the project uses Python)*

- Type hints on all functions.
- Use `pathlib.Path` for file paths.
- Use the `logging` module — no bare `print` for runtime output.
- All constants in a single config module.
- Pin dependencies in `requirements.txt`.
- Use Pydantic for data validation.
- Python 3.9+ compatible unless specified otherwise.

---

## Frontend Standards

*(Apply when the project has a web frontend)*

- Functional components + hooks only. No class components.
- Colors, enums, and constants in a dedicated constants file — never hardcoded inline.
- Data transforms belong in hooks or utility functions, not in components.
- Proper loading, error, and empty states on every view.
- All interactive elements must have visible focus indicators for accessibility.
- **Mobile-first responsive design.** All features must work on both mobile and desktop.
- Use TypeScript strict mode when the project uses TypeScript. No `any` types.
- **Deduplicate image assets.** Serve each image exactly once. Use `<picture>` with `srcset` so the browser selects the best format (AVIF > WebP > PNG) rather than downloading all variants.
- **Serve optimized image formats.** Always use an image CDN or optimization pipeline. Never serve uncompressed PNGs for content images in production.
- **Only load libraries used on the page.** Don't let backend-only dependencies leak into read-only frontend pages.
- **Write descriptive `alt` attributes.** Every content image needs meaningful alt text for accessibility — never leave `alt=""`.
- **Use responsive CSS, not duplicate DOM trees.** Handle mobile/desktop layouts with CSS media queries — never render the same content twice in the DOM.

---

## Network Ethics & Rate Limiting

*(Apply when the project fetches from external sources)*

- Minimum 1.5–2s delay between requests to any single host.
- Set an informative `User-Agent` header.
- Handle 429 responses with exponential backoff (start at 10s).
- Cache all fetched content to disk. Re-runs should never re-download already-cached content.
- If a service persistently blocks after retries, log to `issues.md` and gracefully skip. Never crash.
- Start small when testing scrapers — validate against a handful of pages before scaling to full runs.
- **Use an image CDN or optimization pipeline.** Never serve raw, uncompressed images directly from object storage. Compress and convert to modern formats (WebP/AVIF) before delivery.

---

## AI/API Cost Optimization

*(Apply when the project uses LLM APIs)*

- Use the cheapest model that meets quality requirements by default (e.g., Haiku before Opus).
- Apply keyword pre-filtering to skip irrelevant content before sending to expensive APIs.
- Truncate/excerpt input text to reduce token usage.
- Cache API responses by content hash. Never re-classify identical content.
- Log cost impact at each optimization layer. Print a cost summary at the end of each run.
- `--dry-run` and `--fetch-only` modes must work without an API key.

## Working with AI Agents

*Meta-principles for getting the most out of AI-assisted development.*

- **Context engineering over prompt engineering.** Fill the context window with exactly what's needed — no more, no less. Watch for three failure modes: *context poisoning* (early errors that compound), *context distraction* (irrelevant content that buries what matters), and *context clash* (contradictory instructions).
- **Start fresh on topic switches.** Use `/clear` when moving to an unrelated problem. Long mixed-topic contexts degrade quality. Break complex tasks into small steps and commit between them.
- **AI has no taste.** Actively review output for: excessive try/catch blocks, unnecessary abstractions, code bloat instead of refactoring, and poor judgment on simplicity vs. structure. These are recurring failure modes that require human correction.
- **AI is a tool, not a substitute for engineering discipline.** Always apply fundamentals to AI-generated code: performance auditing, bundle analysis, code review, and optimization passes. High LOC output is meaningless if the code is bloated, duplicated, and unoptimized. Shipping fast doesn't mean shipping well.
- **Closed-loop validation.** Build projects so the agent can compile, lint, run tests, and verify its own output without human intervention. When the agent can close the loop itself, you can trust the result.
- **Keep this file current.** When something unexpected happens — a pattern that failed, a correct CLI invocation, a library quirk — add a concise note here. This file should grow incrementally as organizational scar tissue, not be rewritten from scratch.
- **Write big plans to files.** For large tasks, write the spec to a `docs/` markdown file and review it before executing. This persists context across sessions and allows a second-opinion review before building.
- **Don't spawn research agents when targeted searches suffice.** A broad "research the whole space" agent prompt easily burns 50–100k tokens. Before spawning an Agent for research, ask: could 2–3 direct WebSearch/WebFetch calls inline answer this? Reserve background research agents for genuinely multi-source sweeps where parallelism pays off AND the user's task clearly warrants the cost. When an agent IS needed, scope the prompt tightly — ask for specific facts, not general background.
- **Sweep for orphaned wrapper shells after every commit / push.** Bash `run_in_background` calls that wrap long-running data refreshes — especially polling-loop wrappers like `until ps -p $(pgrep -f "...") >/dev/null; do sleep N; done` — can outlive the process they were watching. Once the watched PID exits, `pgrep` returns empty, `$(pgrep)` is `""`, `ps -p ""` always fails, and the `until` loop can never resolve, so the wrapper shell sleeps forever. Run `pgrep -fl "<project-path>"` (or check `jobs -l`) before declaring a session done; `kill` any lingering wrappers. Two design fixes: (1) prefer the `Monitor` tool over inline `until`+`sleep` polling — `Monitor` cleans up when its body exits; (2) if you must use Bash, invert the test to `while pgrep -f "..."; do sleep N; done` so the loop exits *when* the process disappears, instead of the unsatisfiable `until ps -p $(pgrep)` shape.

## Project-specific notes (Brownfield Opportunities)

- **Connector framework.** All data sources live under `connectors/` and inherit from `connectors.base.Connector`. The connector owns its CLI flags (via `add_cli_args`), its cache key namespace (filename prefix = `slug`), and its normalize logic. The driver (`refresh.py`) handles HTTP infra, schema validation, and output write. To add a source: drop one file in `connectors/`, register it in `connectors/__init__.py`. **Do not** put fetch logic in `refresh.py` itself — it's intentionally thin. Every record MUST set `id` (cross-source unique — Superfund uses raw EPA_ID, ACRES uses `ACRES-<PROPERTY_ID>`, FUDS uses `FUDS-<PROPERTY_ID>`, BRAC uses `BRAC-<SITE_NAME_SLUG>`) and `program` (`"superfund"` | `"brownfield"` | `"fuds"` | `"brac"`). As of v1.7 there are 5 connectors: `superfund-npl`, `epa-acres`, `dod-fuds`, `dod-brac`, `epa-redev` (enrichment-only, joins onto Superfund records).
- **Multi-source loading + lazy program data (v1.7).** `docs/data/sites.json` stays Superfund-only (~170KB gz) for fast first paint. Other programs lazy-load via `ensure*Loaded()` functions that de-dupe parallel fetches via shared promises: `epa-acres.json` (~36k brownfields, 1.5MB gz), `dod-fuds.json` (~8.8k FUDS, ~4MB), `dod-brac.json` (27 BRAC sites, 6KB), `epa-redev.json` (1,905 enrichment records, ~1.2MB). All four default-on; skip any via `?program=superfund` etc. `epa-redev` is special: it enriches existing Superfund records with infrastructure-proximity fields and `data_center_reuse_candidate` rather than adding new sites. All lazy loads fire via `Promise.allSettled()` after first paint; `markAppReady()` triggers after all resolve.
  - **Enrichment loaders must `await` the program promises before applying their join (load-order race, PR #19 / Codex 2026-07-11).** Every all-programs enrichment loader (`ensureInfraLoaded`, `ensureRetiredPlantsLoaded`, `ensurePlannedRetireProxLoaded`, `ensureParcelOwnerLoaded`, `ensureOppZoneLoaded`, `ensureIraEnergyCommunityLoaded`, `ensureFemaNriLoaded`, `ensureClimateZoneLoaded`, …) applies its patch with `const existing = sitesById.get(rec.id); if (!existing) continue;`. But it runs in the SAME `Promise.allSettled(lazyLoads)` fan-out as `ensureAcresLoaded`/`ensureFudsLoaded`/`ensureBracLoaded` with **no ordering guarantee** — so any enrichment file SMALLER than `epa-acres.json` (~10.9 MB) / `dod-fuds.json` (~4.4 MB) resolves first, `sitesById` still holds only the eager Superfund records, and the `!existing` guard silently drops every ACRES/FUDS/BRAC join permanently (the loader never re-runs). Only `infra-proximity` (12 MB, > ACRES) is accidentally safe. **A new all-programs enrichment loader MUST `await Promise.allSettled([acresLoadingPromise, fudsLoadingPromise, bracLoadingPromise].filter(Boolean))` before its apply-loop** (the same guard `applyUrlSelection()` uses; `.filter(Boolean)` because those promises are null for programs skipped via `?program=`). `ensurePlannedRetireProxLoaded` does this; the other pre-existing loaders do NOT yet — tracked as a [high] backlog item (shared `applyEnrichmentWhenProgramsReady` helper). Superfund-only enrichments (echo/docs/redev/ai-summary) don't need it — Superfund is eager. **Testing this needs a forced race** — a fast local `http.server` lets ACRES win, hiding the bug; delay the ACRES/FUDS responses with Playwright `page.route` (see `test_planned_retirement_join_covers_all_programs`).
- **Chunked marker hydration (v1.6).** Adding 36k Leaflet circle markers synchronously froze the main thread for 30+s. `ensureAcresLoaded()` now hands the records to `hydrateMarkersChunked()` which calls `addOneMarker()` for 800 records per `requestIdleCallback` tick (falls back to `setTimeout(0)`); the returned promise resolves after the last batch lands. That's also when `markAppReady()` flips `window.__APP_READY__ = true` and dispatches `brownfield:ready` on `document`. Use those signals from automation; don't poll `epa-acres.json` 200 or `#meta` text.
- **Paginated table (v1.6).** Rendering all ~38k `<tr>` elements into the DOM took the doc to ~265k nodes and tanked DOM-interactive. The table is now paginated at `TABLE_PAGE_SIZE = 250`: `tableState.sorted` / `tableState.filtered` live in memory, only the first N filtered rows are in the DOM, and an IntersectionObserver-driven sentinel (`.table-sentinel`) auto-appends the next page within 300px of the scroll bottom. Filter / sort changes call `rebuildTable()` → `refreshTableForFilter()` (full reset to page 1). `zoomend` calls **only** `applyMarkerVisibility()` — never `applyFilter()` — because zoom changes don't affect the filtered set, only marker decimation. When a marker for a row past the rendered window is selected, `ensureRowRendered(id)` pages rows in until that ID lands so the highlight works. **First-paint DOM ~4,876 nodes (measured 2026-07-11), cap 5,000 — regression-tested in `test_dom_size_under_5k_nodes`.** Breakdown: `view-table` ~2,617 (the 250-row page — the dominant cost), `view-map` ~1,576 (Leaflet), `view-about` ~171; the hidden tab views are **already lazy** (`view-candidates` ~49, `view-ap1000` ~39 — skeleton only, tables build on first activation). So the real DOM lever is the main Table + map, NOT the hidden tab tables — there's only ~124 nodes of headroom, and any new always-rendered column/section can trip the guard (see the reverted parcel-acres table column). Lazy-building the hidden tab views would reclaim <90 nodes; deferring the main Table build until its tab is activated is the only large win but would break the "table rows always exist at load" invariant many e2e tests and the marker→row highlight rely on.
- **JSON serialization.** `Payload.model_dump_json(exclude_none=True)` is critical — without it every ACRES record carries 5+ explicit `null` fields (current_owner, encumbrances, etc.) that bloat the file ~30%. Default is also minified; `--pretty` overrides for diffing.
- **Color tokens are CSS-var-driven.** Two palettes live on `:root` (with `[data-theme="dark"]` overrides):
  - `--status-{final,deleted,proposed,other}` — drive the **NPL status pills only** (table column + detail panel).
  - `--program-superfund` / `--program-brownfield` / `--program-fuds` / `--program-brac` — drive **map markers, legend, and detail-panel top stripe** (set inline as `--detail-stripe` by `selectSite()`). Markers are colored by program (one dot per program), not by NPL status. JS reads via `getComputedStyle(html).getPropertyValue(varName)`. `colorForRecord()` reads `PROGRAM_COLOR_BY_PROGRAM`. **Don't** hard-code marker colors or duplicate the values in CSS — the legend, pill rules, and JS all read the same vars. On theme swap, `refreshMarkerColors()` and `rerenderLegend()` re-paint everything. v1.8 palette: Superfund = `#b8332f` light / `#ef5050` dark, Brownfield = `#1c5e9e` / `#7eb6e8`, FUDS = `#6f3691` / `#b47ad8`, BRAC = `#c46a14` / `#e6a040`.
- **Editorial design system (v1.8).** Hero strip with eyebrow + serif H2 + dek between topbar and filters; KPI deck (`#kpi-total`, `#kpi-acres`, `#kpi-dc`, `#kpi-states`) computed from the in-memory `sites` array (no extra fetches). Below the map, a `<footer class="site-footer">` cites the five data sources. Typography uses a system-serif display stack (`--font-serif: "Charter", "Source Serif 4", ...`) — **don't** add a Google Fonts link, the system stack is intentional for perf and offline-friendliness. KPIs and any new numerals get `font-variant-numeric: tabular-nums`. Hero copy is hidden on mobile (<640px) so the map keeps real estate; KPI deck becomes a horizontal scroll-snap carousel with two-line subtext wrapping. Tablet (<1024px) collapses the two-column hero (copy + KPI deck) to one column. **Don't** introduce backdrop-blur on the map legend or any other map-overlay element — it recomposites every pan/zoom frame and tanks mobile perf.
- **The `[hidden]` trap.** This codebase has been bit twice (detail panel 2026-04-29; filter chip 2026-04-30) by writing `display: inline-flex` / `display: block` on an element that also uses the `hidden` HTML attribute. The CSS rule wins, the attribute is ignored, and the element renders. **Always** add an explicit `[hidden] { display: none }` rule alongside any `display: ...` override. The detail panel takes the slow path (visibility transition); the chip takes the fast path (`display: none`).
- **Place-name prettifier (v1.8).** EPA / USACE source data ships cities, counties, and addresses ALL CAPS or with placeholder sentinels (`-- Not Defined --`, `_NULL_`). `prettyPlace()` in `app.js` runs in `ingestSites()` and overwrites `s.city`, `s.county`, `s.address`. Raw source preserved on `s.{city,county,address}_raw` for debugging. Sentinels collapse to `null`.
- **Site-name prettifier (v1.11.1).** Companion to `prettyPlace()` — `prettyName()` title-cases `s.name` at ingest and overwrites the raw value, with the original preserved on `s.name_raw`. The acronym whitelist (`NAME_KEEP_UPPER`) is the load-bearing piece: it's seeded from a frequency scan of the actual dataset (NIKE, AFB, AAF, AFS, NAS, NRDA, PCB, USDOE, USACE, USDA, USFS, BLM, NPS, USA, US, II/III/IV/…). When a new acronym shows up in a future data refresh that the list doesn't catch, add it to the set — every record on next ingest picks up the change automatically. **Don't** prettify names connector-side without a per-source whitelist — Superfund EPA-name conventions, FUDS USACE-name conventions, and BRAC installation-name conventions are different enough that one global list would mangle ~5–10% of the corpus. Frontend ingest is the right layer for now; promote to connector-side only when a non-frontend consumer materializes.
- **Meta text (v1.8).** `updateMetaText()` derives the topbar subtitle from per-program counts in `sites`. **Don't** hardcode "X Superfund + Y brownfields" templates — they break the moment FUDS or BRAC also lazy-loads (the previous bug had FUDS counts incorrectly labeled "brownfields"). Call `updateMetaText()` after every data load.
- **Last-update date = max `generated_at` across all loaded files (2026-06-01).** The hero eyebrow (`Updated …`), footer (`Refreshed …`), and subtitle (`· refreshed …`) all read `window.__refreshedAt`, which `recordRefreshDate(generatedAt)` (in [app.js](docs/app.js), next to `setHeroRefresh`) keeps as the freshest date seen — it parses each incoming `generated_at`, keeps the max, and re-renders the hero/footer (`setHeroRefresh`) + subtitle (`updateMetaText`). Every data-file load path — the eager `sites.json` fetch plus all 11 `ensure*Loaded()` lazy loaders — calls `recordRefreshDate(payload.generated_at)` as it lands, so the displayed date ticks forward to the newest file (today `epa-superfund-docs.json`, which refreshes on a later cadence than the core Superfund set: 2026-05-26 vs sites.json's 2026-05-12) instead of being pinned to `sites.json`. **Don't** add a new data-file loader without calling `recordRefreshDate()` in its `.then` — same drift-safe-iteration risk as `PROGRAM_LEGEND` (UAT-007); a loader that skips it silently understates freshness whenever its file is the newest. Basemap files (`us-states` / `us-counties`) carry no `generated_at` and are correctly ignored. Guarded by `test_refresh_date_reflects_freshest_data_file` (computes the max in-browser from the data files themselves — no hardcoded date); its file list must gain any newly-added data file.
- **Filter chip (v1.8).** `#filters-chip` shows a small badge on the gear button with the count of active filters. `updateFilterChip()` is called from `applyFilter()`. The chip uses `[hidden]` + `display: none` (see "[hidden] trap" above) to fully remove it from layout when no filters are active.
- **Reset handler must iterate `PROGRAM_LEGEND` (v1.9.1, UAT-007).** The "Reset" button in the filters strip resets `filterState.programs` and re-checks every program box from `PROGRAM_LEGEND.map(p => p.program)` — **don't** hardcode `["superfund", "brownfield"]` or any other subset. When v1.7 added FUDS + BRAC, the reset handler stayed at the v1.6 two-program list and silently dropped FUDS/BRAC on every Reset click; the chip stayed lit and `?program=...` hung around in the URL. Same drift risk as `populateStatusFilter()` — anything that enumerates programs MUST iterate the legend so future programs pick up the change for free. Reset also has to call `ensureFudsLoaded()` / `ensureBracLoaded()` because the user may have arrived via a URL that skipped those programs (`?program=superfund,brownfield`).
- **`text-overflow: ellipsis` needs a non-inline display (v1.9.1, UAT-006).** `.kpi-sub` was a `<span>` — i.e. `display: inline` by default. `overflow: hidden` and `text-overflow: ellipsis` silently no-op on inline boxes; the subtext renders past the cell boundary into the next column instead of clipping with an ellipsis. Always set `display: block` (or `inline-block` / `flex` / `grid`) on any element where you rely on `text-overflow: ellipsis`. Combined with `min-width: 0` on the grid item parent so the column can actually shrink below the intrinsic content width.
- **Marker decimation.** With ~47k markers (1.9k Superfund + 36k ACRES + 8.8k FUDS + 27 BRAC), drawing every point at zoom 4 destroys mobile pan/zoom. `decimateKeep()` keeps 1/8 at zoom ≤4, 1/4 at ≤5, 1/2 at ≤6, all at ≥7. Stable hash-based (`shouldDecimateOut(id, keepEvery)`) so the visible subset doesn't reshuffle on zoom changes. Re-evaluated on `zoomend` via `applyMarkerVisibility()` (cheap — no table rebuild).
- **Auto-fit on filter narrow (v1.6).** `refitMapToFilters()` runs after each user filter change. Heuristics: skip when the visible set is empty or >5k (no meaningful narrow), zoom to 12 for a single result, otherwise `fitBounds` only when the visible bbox is <50 % of the current viewport area. Search and acreage are debounced 350ms so dragging / typing doesn't fitBounds every frame. Reset re-runs `fitBounds(US_BOUNDS)`. Don't call this from `zoomend` — the user's manual zoom would fight itself.
- **Non-CONUS state polygon mask (v1.6).** `drawBasemap()` filters `us-states.json` features whose `properties.name` is in `NON_CONUS_STATE_NAMES` (Alaska, Hawaii, Puerto Rico) before passing to `L.geoJSON()`. The matching markers are remapped via `applyInsetRemap()` into the bottom-of-map inset boxes, so dropping the real-world polygons keeps the visual story consistent. If a future `us-states.json` swap adds new territories with real-world polygons inside `US_BOUNDS`, add their `properties.name` to that set.

- **EPA Superfund Documents filter: doctype, not label allowlist (2026-05-12).** The original `COLLECTION_ALLOWLIST` matched five exact strings ("Key Documents", "SPP Decision Documents", "SPP Public Available Documents", "SPP Technical Reports and Studies", "SPP Enforcement and Settlement Documents"). A label-distribution survey across ~3,500 cached docdata pages revealed those five labels cover **only 1932 of ~3700 SC-typed collections** in the corpus — curators across regions use a long tail of variants: "Publicly Available Documents" (438) and "PUBLICLY AVAILABLE DOCUMENTS" (345) without the "SPP" prefix, "Decision Documents" (150), "Five Year Review Reports" (103), "Five-Year Review Reports" (64), "Five Year Reviews" (62), "Technical Reports and Studies" (77), "Fact Sheets and Public Meeting Documents" (84), and many more. The label-allowlist filter consequently flagged **497 F/D sites (28% of the universe) as "no documents found"** when in fact they had high-value documents under variant labels (e.g. Gurley Pit Superfund had 7 Five-Year Review Reports labeled "PUBLICLY AVAILABLE DOCUMENTS"). The fix is a doctype-based filter (`INCLUDED_DOCTYPE = "SC"`): cumulis tags every collection with `type=SC` (curated public) or `type=AR` (administrative-record docket dump), and the SC vs AR line is EPA's own — no label string maintenance needed. The previous `COLLECTION_ALLOWLIST` is preserved as `EXPECTED_CURATED_LABELS` for documentation but not enforced. **Don't** revert to label-allowlist filtering — the label space is open-ended across 10 EPA regions; the type column is the stable contract. The base-class helpers `Connector.existing_records()` / `Connector.existing_ids()` / `Connector.merge_records_by_id()` live in [connectors/base.py](connectors/base.py) and read from `Connector.OUTPUT_DIR` (a class attribute, monkeypatched in tests). **Don't** support `--missing-only` on producer connectors (`superfund-npl`, `epa-acres`, `dod-fuds`, `dod-brac`) — those re-fetch from the source-of-truth API and *replace* the dataset every run; "missing record" has no meaning when the producer is itself the canonical state. The `getattr(args, "missing_only", False)` access pattern means the flag is silently a no-op on producers, which is the right behavior. **`infra-proximity` short-circuits the ~6-minute index build when missing_only filters everything to zero** — that's the design payoff; without the early-return, "I just want to top off after adding new sites" would still pay full index-build cost. The merge predicate is keyed on `id` for all four (matches every output file's primary key), with `epa_id` as the look-up alias for `epa-superfund-docs` since its loader returns either field as the de-facto key. Same drift-safe iteration risk as `PROGRAM_LEGEND` (UAT-007): if a fifth enrichment connector ships, wire it through by following the existing four-step pattern (filter sites before skip/take, merge before return) — there's no global hook in `refresh.py` because each connector knows its own "covered" predicate.

- **Resumable flood backfill: seed + `--infra-flood-budget` (v1.22, 2026-06-16).** The per-site FEMA flood layer is a ~15-hour full run, so it's backfilled incrementally across scheduled-task sessions. Two mechanics make it cleanly checkpointable. (1) **Seed** — at the top of `fetch_records`, `flood_zone`/`in_sfha` are loaded from the existing `docs/data/infra-proximity.json` into `flood_seed` and carried forward verbatim (no re-query — the FEMA answer for a fixed lat/lon doesn't change). This is load-bearing: every `rec` is rebuilt fresh from the spatial indexes each pass (`rec = {"id", "program"}`), so WITHOUT the seed an interrupted/partial run would re-null every site it populated last run. (2) **Budget** — `--infra-flood-budget N` caps NEW fetches (cache misses) at N; cache hits and seeded sites are free and never consume budget. A budgeted run = index build + harvest-all-cached + up-to-N new fetches + **full-record-set write** (never truncates — all 46,760 records always emitted). The cache key is centralized in module-level `_flood_cache_key(lat, lon)` (shared by `_query_flood_zone` and the budget's cache-existence check so they can't drift). **The ~15-min fixed cost per run is the `rail` SegmentIndex build (111k polylines / 2.77M segments) — it dominates; transmission/highway/gas/substation/power_plant are seconds.** So size budgets to amortize it (don't run budget=50; run budget≥1000). **Cache is the durable progress, not the file**: if a run is killed before the final write, its fetches are still cached, and the next run seeds the file's prior values AND harvests those cached fetches for free — nothing is lost. **Always run the FULL connector (no `--infra-skip-*`) for a flood backfill** — skipping the other layers would null their fields in the write (the "don't run with all skip flags" trap). Don't use `--missing-only` for flood: all 46,760 ids are already "covered," so it skips everything. Checkpoint cadence: prior sessions did ~+1,500 sites/run (e.g. 8,338→9,900 on 2026-06-09). Reverse: every schema field that `app.js` reads off a site must be cited, listed in `COVERED_BY_PARENT` (a sub-field explained by its parent row, e.g. `transmission_kv` under `transmission_mi`), or in `INTERNAL` with a reason. **When you add a user-visible field, one of those three lists has to change or CI fails** — which is the point: an uncited number is exactly what the evidence panel exists to prevent.

- **Janus screening is parcel-unknown and rank-neutral.** `scripts/build_janus_nepa.py` runs pinned `nepa-mcp==0.1.1` from an isolated Python 3.12 tool environment and writes `janus-nepa.json` plus per-site GeoJSON. Coordinates are installation reference points. Most layers use 10 miles; PAD-US/federal-land point context uses 0.1 mile. USACE results identify district and delineation region only—never wetland presence or CWA jurisdiction. Cache explicit timeouts as unavailable; `--site` merges into the existing nine-site inventory instead of replacing it. The Microreactors view exposes sources/maps but no composite risk score.
- **All-program enrichments wait for program ingest.** `tribal-areas` must await ACRES/FUDS/BRAC promises before joining, or fast enrichment downloads silently drop lazy-program records. Its output is sparse positive-only (2,122 hits, not 46,759 true/false rows) because the UI makes no negative claim. ## Universal lessons learned here

Mirrored into the canonical [`coding-best-practices/CLAUDE.md`](/Users/pranava/Projects/coding-best-practices/CLAUDE.md) in the same pass — kept here too because this is the file that actually loads into context when working in this directory. Companion-file detail lives in that repo's `TESTING.md` (invariant validation, fuzzing an index against brute force, proving a guard fails, stray port listeners) and `DATA.md` (thresholds that can't span the data, not deleting on a heuristic, HTTP-200 API errors, citations that resolve to the claim, PDF extraction).

- **A checker that does not model the real object measures nothing, and it will tell you so as a finding.** Twice here on the same mistake. `validate_data.py` merged enrichment over program records with overwrite precedence while the browser's join is fill-if-empty, so `epa-redev` coordinates replaced NPL ones and `infra-lipschitz` reported **2,146 violations that did not exist**. Then the evidence link checker sampled bare program records instead of enriched ones and **"passed 40/40" while exercising one of fourteen fields**. One produced alarming output, the other reassuring output; neither measured the thing. Any tool that builds a merged view MUST replicate `Corpus.merged`'s fill-if-empty semantics. Corollary: **a validator mirrors the code it verifies, not an improved version** — making `dc-candidate-recompute` fall back to the authoritative NPL acreage "to be more correct" produced 38 instant false mismatches, because it began measuring a policy nobody implemented.
- **Prove the guard fails.** A new assertion never seen red is a hypothesis. Copying a research PDF into `docs/` to watch `test_published_tree.py` go red took ten seconds and was the only evidence the guard worked.

### 2026-08-21 (two-week sweep harvest)

- **A root cause recorded in `backlog.md`/`issues.md` is a hypothesis someone wrote down once, not a finding — re-read the code before implementing the logged fix.** A filed item read "`_run_one()` already returns a per-connector rc; honour it and continue," but the `--all` loop *was* already honouring it; reading the code shrank the fix to something far smaller than the filed plan. Filed diagnoses rot exactly like filed rosters do, and they carry more authority than they earned because they're written in the imperative. Cost of checking: one file read. Cost of skipping it: implementing a fix for a bug that isn't there.

### 2026-08-23 (specs research + coal-PR review session)

- **Hand-curated catalog rows can be stale the day they're written** — Cumberland's retirement was reversed by TVA's board six months before our "retires 2028" row was typed. Per-row `source_url`+`verified_at`, validator enforcement, and a domain-expert verification pass BEFORE first ship are the fix; a quarterly audit can't resurrect a row that was born dead. (Mirrored to coding-best-practices `DATA.md`.)
- **"Prove the guard fails" applies to shell gates too**: `python3 - <<EOF … EOF || echo` swallows the exit and the following `[ $? -ne 0 ]` tests the echo — pr_gate's citation-liveness step shipped unable to fail and a review agent caught it by seeding the exact defect it guarded. Capture `rc=$?` on the next line; red-prove new gates like test guards. (Mirrored to coding-best-practices `TESTING.md`.)
- **Inline `onclick` + `escapeHtml(x).replace(/'/g,"\\'")` is a provable no-op stack** — the entity-escape eats the quotes first, then the HTML parser decodes them back into the handler's JS. Delegation + `dataset` (which decodes entities) or closure-bound listeners; never interpolate data into handler strings. (Mirrored to coding-best-practices `SECURITY.md`.)
- **A fresh worktree inherits `.claude/launch.json` pointing at the PREVIOUS worktree's docs/** — the stale-path trap fires on every new worktree, not just the one that first documented it. Repoint before `preview_start`, and check `lsof -nP -iTCP:8765 -sTCP:LISTEN` for a stray `scripts/serve.py` (a 5-hour orphan was squatting the port again this session).
- **A hidden Browser-pane tab reports viewport 0×0 and `requestIdleCallback` starves** — chunked marker hydration never finishes, `__APP_READY__` never flips, and every marker count reads 0. That's the pane, not the app: front the tab before trusting DOM measurements, or rely on the headless e2e suite (real viewport) for anything hydration-dependent.
- **X.com bookmark reading via Chrome**: nested quote-card embeds swallow wheel scroll; the `j`/`k` keyboard navigation steps the timeline reliably and each `j` re-anchors the viewport. Bookmarks → `x.com/i/bookmarks`, then `j` + screenshot per post.
- **Agent retrospective (2 agents, ~487k tokens total, both justified).** The domain agent (24 primary-source checks, ~221k) caught Cumberland/SRS-units/Lewis-Ridge-MW/ERCOT-pause — errors my inline sweep missed because I'd verified marquee rows and back-filled the rest; catalog-wide claim verification is genuinely multi-source work, the case agents are FOR. The code agent (~266k) found 15 issues including two HIGH in paths no test exercised — and one bug in a gate I wrote *that same session*, which is the argument for a second set of eyes that isn't the author. Waste identified: ~30% of the domain agent's checks re-verified rows the prompt had marked pre-verified — next time put the skip-list in a numbered table the agent must echo back, not prose.
